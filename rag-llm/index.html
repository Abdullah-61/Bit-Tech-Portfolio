Project 1

Industrial Maintenance Management Platform

Maintenance engineers query manuals, work orders, and compliance documents in natural language. The AI must be accurate, safe, and route each query to the right data handler.

ChromaDB Azure OpenAI LangChain NeMo Guardrails FastAPI

Response Handlers Engineered

  • parts_answer — parts table queries
  • staff_answer — staff-related queries
  • technical_answer — asset document referencing
  • ppm_handler — planned preventive maintenance

NeMo Guardrails Integration

  • Input validation — reject out-of-scope questions
  • Output validation — detect hallucinated answers
  • Intent classifiers tuned to manufacturing domain
  • 13+ QA issues resolved through systematic iteration

QA Approach

Systematic query log review → identify failure pattern → fix handler prompt → verify fix doesn't regress others → next iteration. ~30 tracked queries, 13+ resolved per cycle.

How we deliver

  • Ingest & index: Manuals, work orders, and compliance docs chunked and embedded into ChromaDB.
  • Route by intent: Queries parsed by an intent classifier and sent to the correct handler.
  • Specialised handlers: parts_answer, staff_answer, technical_answer, ppm_handler — each tuned for its slice of maintenance data.
  • Guard input & output: NeMo rejects risky queries before the LLM; output rails block hallucinated answers.
  • Grounded answers: LLM retrieves context from ChromaDB and responds with source-backed output.
  • Iterate in production: Query logs drive handler prompt fixes without regressing other flows.

Normalisation Engine

Mixed feet-inches to decimal, fractions, dimension spacing, grade rules, DRYWALL-specific rules, reverse tuple matching, unit inference with context rules.

LLM as Final Gate

llm_check_similar() sends candidate pair to gpt-4o mini for a binary yes/no match — catches fuzzy false positives that pass the score threshold.

Human Review Flags

Low-confidence matches are flagged for human review rather than silently dropped — keeping the pipeline auditable.

How we deliver

  • Upload takeoff: Spreadsheet with natural-language material descriptions.
  • Normalise text: Units, abbreviations, and product family names standardised before matching.
  • Fuzzy retrieval: Candidate SKUs scored against the vendor database.
  • LLM gate: Every fuzzy candidate gets a binary accept/reject from gpt-4o mini.
  • Review queue: Borderline rows flagged for humans before export.
  • Estimates out: Approved matches compiled into PDF and Excel reports.

Project 3

Internal Document Q&A System

Upload any document, ask questions in natural language, get grounded answers. NeMo Guardrails block misuse and hallucinations on both the input and output side.

ChromaDB LangChain NeMo Guardrails OpenRouter FastAPI

Any Document Format

PDFs or text files chunked, embedded, and stored in ChromaDB for semantic retrieval.

Malicious Input Detection

Input rails reject prompt injection, jailbreaks, and out-of-scope questions before they reach the LLM.

Hallucination Guard

Output rails verify answers are grounded in retrieved context — speculative answers are blocked.

How we deliver

  • Upload: PDF or text via the web UI.
  • Index: Chunking, Azure OpenAI embeddings, storage in ChromaDB.
  • Ask: Natural-language questions against the indexed doc.
  • Screen input: NeMo rails catch injection, jailbreaks, and off-topic queries.
  • Retrieve: Semantic search passes relevant chunks to the LLM with context.
  • Validate output: Answers must be supported by retrieved context or they are blocked.

Feature Engineering

  • 5-game rolling averages per player per stat
  • MinMax scaling for feature normalisation
  • Opponent defensive rating features
  • Home/away context encoding
  • Back-to-back game fatigue flag

XGBoost

Gradient boosted trees for mixed tabular features, non-linear interactions, and strong generalisation on sports box-score data.

Training & fine-tuning

Train/validation splits with iterative hyperparameter tuning (learning rate, depth, estimators) per stat.

Per-stat architecture

Dedicated models per target instead of one multi-output head — independent calibration per stat category.

How we deliver

  • Ingest history: Clean game logs and box scores into a reproducible training table.
  • Engineer features: Rolling windows, scaling, and contextual flags aligned to each stat.
  • Train per target: Fit and validate separate XGBoost models for FGM, FGA, FG3M, and MIN.
  • Tune carefully: Iterate hyperparameters to reduce error without overfitting noisy game samples.
  • Serialize for inference: Export models for the live pipeline and versioned retraining.

Live inference stack

Batch → Real-time Conversion

The baseline predicted from static pre-game snapshots. The upgrade ingests live in-game signals, rebuilds features on a polling loop, and re-runs inference as the game evolves.

RapidAPI PostgreSQL FastAPI Polling + feature rebuild

Before — batch

  • Pre-game prediction only — static before tip-off
  • No live ingestion during the game
  • Could not react to foul trouble, injuries, hot streaks
  • Outputs stale within minutes of tip-off

After — real-time

  • Live score, stat, and pace data via RapidAPI mid-game
  • Feature vector rebuilt each polling cycle
  • Inference re-runs with updated in-game context
  • Predictions track live game state continuously

Real-time API integration

RapidAPI sports feed

Live scores, box stats, and play-by-play polled during active games

Polling & feature rebuild

Interval polling; vectors assembled from live stats plus stored rolling averages

PostgreSQL state store

Historical averages and profiles persisted for instant rolling features at inference time

How we deliver

  • Subscribe to live data: Poll the sports feed while games are active.
  • Merge state: Combine API snapshots with PostgreSQL rolling history.
  • Rebuild features: Recompute scaled inputs on every cycle.
  • Re-infer: Run XGBoost with the latest in-game vector.
  • Stay fresh: Outputs track momentum, pace, and lineup effects as they happen.

Alternative data & sentiment

Sentiment Analysis Integration

Social and search signals sit alongside structured model outputs — useful for spotting when statistical projections diverge from public narrative and market pricing.

How it's used

Sentiment scores are combined with model outputs to flag divergence — where statistical projections and public narrative disagree, surfacing candidate mispricings next to current lines.

How we deliver

  • Ingest text signals: Pull social and search feeds on a controlled schedule.
  • Score sentiment: Normalise outputs into comparable sentiment features.
  • Fuse with ML: Layer sentiment alongside XGBoost predictions in one view.
  • Contrast vs. market: Compare fused signals to posted lines for discrepancy analysis.
